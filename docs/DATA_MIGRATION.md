# Data Migration & Compatibility

## اصل طلایی

**داده کاربر مقدس است.** هیچ مهاجرتی تخریب‌کننده نیست و هر عملیات مخرب قبل از اجرا یک نقطه بازیابی می‌سازد.

## IndexedDB

| مورد | مقدار |
|---|---|
| نام دیتابیس | `GermanPersianDictionary` (بدون تغییر) |
| نسخه legacy | ۶ (storeهای: `words`, `favorites`, `examples`, `practiceHistory`, `chatHistory`, `music`, `books`) |
| نسخه جدید | ۷ — فقط افزایشی: ایندکس‌های اضافی + store جدید `restorePoints` |

Dexie با declaration v6 همان schema را بازسازی می‌کند؛ v7 فقط ایندکس اضافه می‌کند و `updatedAt` را برای رکوردهای قدیمی پر می‌کند. **ID رکوردها هرگز تغییر نمی‌کنند** — بنابراین داده‌های SRS و علاقه‌مندی‌ها پیوند خود را از دست نمی‌دهند.

## localStorage (کلیدهای حفظ‌شده)

`srsData`، `lastSrsUpdate`، `dictionary_tags`، `darkMode`، `fontSize`، `theme`، `learningLang`، `wordListSort`

کلیدهای جدید فقط پیشونددار (`lingo-*`) هستند تا با legacy تداخل نکنند.

## فرمت خروجی

خروجی جدید دقیقاً همان شکل legacy است:

```json
{
  "version": 5,
  "schemaVersion": 2,   // فیلد جدید — برای legacy ناشناخته و نادیده گرفته می‌شود
  "exportedAt": "…",
  "words": [...], "favorites": [...], "examples": [...],
  "practiceHistory": [...], "tags": [...], "srsData": {...}
}
```

`schemaVersion` افزایشی است؛ نسخه قدیمی آن را نادیده می‌گیرد.

## الگوریتم SRS

Leitner نسخه قبل عیناً حفظ شده تا رفتار داده‌های قدیمی ثابت بماند:
- سطح ۰–۵، صعود با جواب‌های متوالی درست (۱/۲/۳/۴/۵ جواب → سطح ۱/۲/۳/۴/۵)
- دو خطای متوالی → کاهش یک سطح و صفر شدن شمارنده
- بازه‌ها: `[1, 2, 4, 7, 14, 30]` روز
- `nextReviewDate = lastPractice + interval[level]`

تست‌های `src/test/srs.test.ts` این رفتار را قفل کرده‌اند.

## جریان import امن

1. فایل با zod اعتبارسنجی می‌شود (`legacyExportSchema`)
2. پیش‌نمایش تعداد رکورد به کاربر نشان داده می‌شود
3. **نقطه بازیابی خودکار** از داده فعلی ساخته می‌شود (store `restorePoints`، پنجره چرخشی ۵ تایی)
4. رکوردها با `put` (نه `add`) نوشته می‌شوند تا ID حفظ شود
5. در صورت خطا، بازیابی با یک ضرب ممکن است
